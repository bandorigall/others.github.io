(경로: others.github.io/sorter/)

■ 현재 상태 (2026-08-01)
  - 캐릭터 60명 이지선다 → 1~60위 순위표. 완성, 배포됨.
  - 화면 3개: 시작 / 대결 / 결과.
  - 기능: 비김(둘 다 좋아) · 되돌리기 · 중간저장(이어하기) · 키보드 조작
          · 결과 PNG 저장 · PNG 클립보드 복사 · 순위 텍스트 복사.
  - 반응형: 모바일에서도 카드 2장 좌우 배치. safe-area 대응.

■ 정렬 알고리즘 (핵심 결정)
  상향식 병합정렬 + '답변 로그 재생' 방식.
    - 비교 결과를 answers 배열에 순서대로 쌓고, 화면을 그릴 때마다
      정렬을 처음부터 다시 돌린다. 답 없는 쌍을 만나면 예외를 던져
      그 쌍을 질문으로 띄운다.
    - 덕분에 되돌리기 = 로그 pop 후 재실행, 이어하기 = 로그만 저장.
      상태머신/스택 저장 같은 복잡한 구조가 필요 없다.
    - 60명 재정렬은 1ms 미만이라 매 질문마다 다시 돌려도 무방.
  ★ 검증(node, 각 300회 시뮬레이션):
      완전순서 오라클  → 항상 정확히 정렬. 평균 질문 281.8회, 최대 293회
      비김 다수 오라클 → 무한루프 없이 종료. 평균 280.7회, 최대 291회
    진행률 분모 EST_TOTAL = n*ceil(log2 n) - 2^ceil(log2 n) + 1 = 297.
    최대 실측(293)이 분모보다 작으므로 진행률이 100%를 넘지 않는다.
  ※ 비김은 질문 수를 줄이지 못한다(측정으로 확인). 안내 문구에 그렇게 적지 말 것.
    비김의 효과는 '공동 순위로 묶여 순위가 정확해지는 것'.

■ 데이터
  - 레포 최상단 characters.json 이 단일 원천(60명 = 12밴드 × 5명).
  - build_assets.py 가 그걸 읽어
      assets/<id>.webp     420x560 대결용 카드 (평균 45KB, 총 2.7MB)
      assets/<id>_t.webp   132x176 결과표 썸네일 (평균 8.5KB, 총 508KB)
      data.js              window.SORTER_DATA (fetch 없이 로드 → file:// 도 동작)
    를 생성. assets/ 와 data.js 는 자동생성물이므로 직접 고치지 말 것.
  - 결과표는 썸네일만 쓰므로 60장 다 떠도 508KB. 대결 화면은 2장씩 lazy + 다음 2장 프리페치.

■ 결과 이미지(PNG)
  외부 라이브러리(html2canvas 등) 없이 Canvas 2D 로 직접 그린다.
  1080px 폭, 3열 × 20행, 밴드색 막대 + 썸네일 + 등수 + 이름 + 밴드.
  CDN 의존이 없어 오프라인·CSP 환경에서도 안전.
